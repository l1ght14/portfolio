// 01 — selected work

Production problems I diagnosed and fixed

Real engineering stories from my current role: what broke, what I changed, and what it improved. Each one is a system I worked on directly.

Tradxlink · Tradvisor

Retrieval security in a multi-tenant RAG system

Problem
Public and private platform data shared one Milvus layer, and visibility paths were not enforced before retrieval — so a query could reach another user's private data.
What I did
Enforced member-scoped access controls in the query engine before vector retrieval, tightened path visibility, and moved the restriction into the retrieval layer instead of relying on the model not to disclose it.

→ Unauthorized cross-user data no longer retrievable through the query path.

Tradxlink · Tradvisor

Cutting RAG latency from 30+ seconds to under 10

Problem
Response generation used an older model with a tree-summarizer flow that triggered several model calls per answer, inflating latency and token spend.
What I did
Upgraded the generation model, replaced tree summarization with a compact single-pass strategy, removed redundant API round-trips, and tuned the retrieval/response flow.

→ Under 10 s responses and roughly 50% lower AI cost.

Tradxlink · document AI

Making 300-page documents work

Problem
Very large PDFs produced enormous serialized query-engine and document-index objects that could not be stored safely in MongoDB, breaking ingestion and retrieval.
What I did
Changed the persistence model: large payloads moved into GridFS, MongoDB kept only references, and the runtime index/query objects were reconstructed on demand instead of stored inline.

→ Large documents became supportable without oversized-string failures.

Tradxlink · data pipelines

From government crawlers to a queryable AI system

Problem
DGFT and RBI notification pages did not match the crawler's field mappings, so enrichment received wrong metadata. CBIC could not be scraped directly at all.
What I did
Corrected the crawler mappings, improved LLM enrichment and tax parsing, routed CBIC through a controlled metadata source, then bridged every notification into the RAG platform through its attachment and advanced-query APIs.

→ Trade notifications became structured, enriched and queryable conversationally.
